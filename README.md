# MNT Revenue

*Measure. Navigate. Transform.* — sales intelligence and revenue operations for growing B2B teams in India, by MNT Analytics.

This is a localhost demonstration. All data is synthetic, for a fictional company ("Sahyadri Tech Solutions Pvt Ltd", Pune). No paid APIs or cloud services are needed.

## Run it

Requires Node.js 24 or later (uses the built-in `node:sqlite`).

```bash
npm install
npm run dev        # API on :4000, web on :5173
```

Open http://localhost:5173. The database (`data/mnt-revenue.db`) is created and seeded automatically on first start.

## What works

- **Pipeline**: drag-and-drop board and filterable table; create, edit, move and close deals (lost deals require a reason); close-date pushes are tracked.
- **Deal workspace**: stage stepper, activity log, follow-ups, stage history, health score with the factors behind it, recommended next actions, template email draft.
- **Follow-ups**: overdue / today / upcoming / done, complete and reschedule inline.
- **Accounts and contacts**, including an "expansion" filter for customers with no open opportunity.
- **Forecast**: commit / best case / pipeline build-up against target, scenario sliders, per-rep view, historical vs configured stage win rates.
- **Analytics**: quarterly won vs target, funnel conversion from stage history, source and product performance, loss reasons, activity trend, team leaderboard.
- **Insights**: rule-based findings (coverage, forecast gap, risk, overdue work, source quality, bottlenecks, coaching, concentration, expansion), each with its evidence and a link to act on it, plus a daily briefing.
- **Import / export**: CSV import with column auto-mapping, Indian amount formats (`12.5 L`, `1.2 Cr`, `12,50,000`) and `DD/MM/YYYY` dates, dry-run validation; CSV export with spreadsheet formula-injection protection.
- **Settings**: pipeline stages and probabilities, quarterly targets (team and per rep), users and roles, audit log.
- Indian fiscal year (April–March, e.g. Q3 FY27 = Oct–Dec 2026) and lakh/crore formatting throughout.

## How "AI" is used — and isn't

- Every number (totals, win rates, forecasts, coverage) is calculated in code from the records in the database. No language model computes financial figures.
- Risk and priority scores are deterministic and explainable (`shared/scoring.ts`); each score lists the factors that produced it.
- Insights and the briefing are generated by rules (`server/services/insights.ts`).
- **Optional local LLM (untested)**: if `OLLAMA_URL` (and optionally `OLLAMA_MODEL`) is set, the briefing text is sent to a local Ollama instance for rephrasing only. The response is discarded if any figure in it differs from the original. This adapter has not been tested against a running Ollama server; without it, the app uses the rule-based text and labels it as such.

## Limitations

- **No external integrations.** Zoho CRM, HubSpot, Salesforce, Gmail/Outlook, calendars, web forms and Power BI are listed on the Import page as "Not connected". They are not implemented; CSV import/export is the only working data path.
- **Emails are not sent.** Email drafts are templates to copy into your own mail client.
- Authentication is local (scrypt-hashed passwords, HttpOnly session cookie). There is no SSO, password reset or email verification.
- The schema carries `org_id` on every table so it can become multi-tenant, but only one organisation exists and there is no tenant sign-up.
- SQLite is used for the demo; a production deployment would move to a server database.
- Set `MNT_DEMO=false` to hide the demo-user shortcuts on the login page and disable the in-app demo reset.
